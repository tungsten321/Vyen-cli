# Web Tools (R2.3: web_fetch & web_search) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement production-grade `web_fetch` and `web_search` tools in `vyen-cli` featuring a 100% free, zero-key tri-engine fallback (DuckDuckGo Lite, TinyFish, Parallel) and strict SSRF / DNS-rebinding protection.

**Architecture:** Create `src/web.ts` encapsulating IP validation (rejecting loopback, private, link-local, and cloud metadata addresses), DNS resolution with connection-level IP pinning to defeat DNS rebinding attacks, manual 3xx redirect re-validation, streaming response size capping (5MB max), and HTML-to-markdown conversion with Jina Reader fallback. Implement multi-engine keyless search querying DuckDuckGo Lite first, with automatic fallback to TinyFish MCP and Parallel MCP on rate limits or errors. Wire both tools into `src/tools.ts`, `src/context.ts`, `src/harness.ts`, and `src/help.ts`, and enforce domain policy (`allow`, `ask`, `deny`) across all 4 execution runners.

**Tech Stack:** TypeScript 5.9 strict (NodeNext), Node.js native `node:dns/promises`, `node:net`, `node:http`, `node:https`, `node:test`, Zod schemas.

## Global Constraints

- Target platform: Node >= 22.16, TypeScript 5.9 strict (NodeNext), Linux/Termux/Windows compatible.
- Zero-cost & zero-key: `web_search` uses DuckDuckGo Lite with fallback to TinyFish keyless and Parallel keyless; no paid APIs required.
- SSRF protection: reject all loopback, private, link-local, and cloud metadata IPs; pin resolved IP to prevent DNS rebinding.
- Re-check safety and domain policy after every HTTP 3xx redirect.
- Four-place wiring: `src/tools.ts`, `src/context.ts`, `src/harness.ts`, `src/help.ts`.
- Four-runner policy enforcement: `cli.ts`, `subagents.ts`, `network.ts`, `workflow.ts`.
- Instruction budget: keep combined `AGENTS.md` + `AGENT_LEARNINGS.md` under 24,000 characters.
- Gate before done: `npm run lint` 0 errors, `npm run typecheck` exit 0, `npm test` 0 failures.

## Review Focus

1. `web_fetch` refuses requests to private, loopback, link-local, and cloud metadata IP addresses even when resolved via a public domain name (SSRF prevention).
2. `web_fetch` re-evaluates SSRF safety and domain policies on every HTTP 3xx redirect before fetching the target.
3. `web_fetch` pins the validated IP address to prevent DNS rebinding attacks between check time and connect time.
4. `web_search` queries DuckDuckGo Lite without an API key, parses organic results, and automatically falls back to TinyFish Keyless and Parallel Keyless if rate-limited or blocked.
5. `web_fetch` and `web_search` enforce strict payload size caps (5MB max) and redirect depth limits (max 5 redirects), and respect domain policy (`allow`, `ask`, `deny`).

### Task 2: Implement Core Engine in `src/web.ts`

**Files:**
- Create: `src/web.ts`

**Interfaces:**
- Export `isPrivateIp(ip: string): boolean`: returns true for loopback, RFC 1918 private, link-local, and AWS/GCP metadata (`169.254.169.254`).
- Export `resolveSafeIp(hostname: string): Promise<string>`: uses `dns.promises.lookup`, throws if hostname resolves to private/loopback/metadata IP.
- Export `webFetch(options: WebFetchOptions): Promise<WebFetchResult>`:
  - Custom `http.Agent` / `https.Agent` pinning connection to the resolved safe IP address (defeating DNS rebinding).
  - Manual redirect loop (`maxRedirects: 5`): re-checks safe IP and domain policy on each 3xx response.
  - Streaming collector capping response size at `MAX_RESPONSE_BYTES = 5 * 1024 * 1024` (5MB).
  - Converts HTML response to Markdown with fallback to Jina Reader on complex SPA or Cloudflare challenges.
- Export `webSearch(options: WebSearchOptions): Promise<WebSearchResult>`:
  - Queries `https://lite.duckduckgo.com/lite/` with form POST `q=<query>`.
  - Parses organic result links (`uddg` decode) and snippets, stripping HTML tags.
  - On error or rate limit, automatically falls back to `https://agent.tinyfish.ai/mcp` (`X-TinyFish-Access-Mode: keyless`).
  - If TinyFish is unavailable, falls back to `https://search.parallel.ai/mcp` (keyless MCP).

## Post-review corrections (2026-11-01)

The first review found that `web_fetch` failed for every real hostname with
`Invalid IP address: undefined`: the pinned `lookup` callback returned a scalar while
Node's `autoSelectFamily` path calls it with `{ all: true }`. The green suite missed it
because every test used an IP literal, for which Node skips `lookup`.

Corrections made in this pass:

- `resolveSafeAddresses` returns every validated address; the `lookup` callback honors
  `{ all: true }` and the requested family, preserving IPv4/IPv6 fallback.
- Redirect targets that require approval (`ask`) now fail closed unless an approval
  callback approves them.
- `domain:` matching strips a trailing dot from the URL hostname and the rule pattern.
- Non-HTML text is no longer tag-stripped or entity-decoded; binary content types are
  rejected. HTML→Markdown conversion happens only for HTML responses.
- `web_fetch` has a 30-second total deadline (not only socket inactivity), a 32,000
  character model-visible cap, and rejects 3xx responses without `Location`.
- DuckDuckGo Lite parsing filters ads/help links and unescapes hrefs.
- `domain:` is documented as `web_fetch`-only; `web_search` rules match the query text.
- The Jina Reader fallback described in Task 2 is intentionally not implemented: it
  would send the target URL to a third party and needs its own policy/SSRF review.
- New tests cover the hostname lookup contract, content-type conversion, redirect
  approval, missing `Location`, behavioral size cap, model cap, total deadline, ad
  filtering, trailing-dot policy, tool registration/aliases, and the Parallel fallback.
